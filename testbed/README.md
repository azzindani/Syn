# testbed — live Office run area

Everything a real Windows + Office run touches lives here, and everything
except this file is gitignored. Nothing in a live test should ever be written
outside this directory: the scripts in `scripts/` and `tests/capability/`
build and open their documents here, so a misfired write lands on a
throwaway document, not your work.

```
testbed/
  docs/   documents the sidecar attaches to (plan.xlsx, report.docx, deck.pptx)
  out/    exports produced by the `export` op
  logs/   REPL journals, sidecar stdout, run transcripts
```

`docs/` is regenerated by `scripts/new-testbed-docs.ps1`, so deleting the
whole directory is always safe — that is the intended way to reset.

Why in-repo rather than `%TEMP%`: a live COM run is only trustworthy if you
can read back exactly what it did. Keeping the artifacts beside the code means
a failed run leaves evidence next to the source that produced it, and a
`git status` that stays clean proves nothing leaked into the tree.
